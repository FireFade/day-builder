# Day Builder v0.5 — QA звіт

## Перевірено автоматично
- 37 pytest-тестів, Python FastAPI/SQLite, усі успішні.
- Прогін Alembic 0001–0004; окреме оновлення тестової v0.4 бази з наявною Google-подією, планом і зашифрованим записом підключення.
- Синтаксис JS (`node --check`) і Python (`compileall`).
- Chromium: інтерфейс з мокованими API-відповідями при 390×650, 1100×680 та 1440×900 px; без JS-помилок.
- Запущений локальний FastAPI: реальні HTTP-запити на створення завдань, генерацію дня, зміну часу, Undo/Redo й експорт `.ics` — PASS.
- Окремі API-тести: пересування, закріплення, конфлікти, редагування й видалення власного блоку, збереження при генерації, Undo/Redo, пропуск, .ics, read-only календар.

## Що перевірити вручну після встановлення на Windows
- Реальна Google Calendar синхронізація з твоїм уже авторизованим акаунтом після перенесення трьох конфіденційних файлів.
- Підтвердження змін та перевірка, що редагована активність не збиває інші зустрічі.
- Drag/drop мишею у твоєму браузері та мобільні ↑ ↓.
- Налаштування дозволів на повідомлення у конкретному браузері.
- Кнопка `Скасувати` після перезапуску Day Builder.
- 125%/150% масштабування Windows і висоти екрана 600–800px; переконайся, що у вікні активності є прокрутка, а кнопка «Зберегти» видима.
- Імпорт `.ics` у бажану програму календаря без дублювання вихідних зустрічей.

## Відомі обмеження
- Браузерні нагадування без server-side Web Push: працюють лише при відкритій вкладці, можуть затримуватись у фоні.
- Вільне перетягування доступне лише усередині сумісного неперервного сегмента незакріплених блоків; для перенесення через зустріч використовується точне редагування часу.
- `frontend/` React/TypeScript — старіша експериментальна альтернативна оболонка, нові v0.5 дії реалізовані й тестовані у головному `web/` інтерфейсі.
- SaaS-авторизації користувачів немає, сервер має залишатися на 127.0.0.1.
- Онлайн Google OAuth і реальний Windows запуск v0.5 у цьому середовищі недоступні; робочий сценарій потрібно перевірити з користувачем.
